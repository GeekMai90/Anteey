# 账号登录功能开发需求

## 一、功能概述

实现基于账号系统的会员权限管理，替代原有的激活码系统，同时保留原有激活码功能作为备用。

## 二、具体需求

### 1. 用户认证

- 支持邮箱密码登录
- 本地保存登录状态
- 支持自动登录
- 支持登出功能
- 支持token刷新
- 设备数量限制（最多2台）

### 2. 权限管理

- 未登录/免费会员：限制100张卡片
- 桌面端永久会员：无限制使用所有功能
- 本地缓存权限信息180天
- 有网络时自动更新缓存

### 3. 设备管理

- 使用机器码作为设备唯一标识
- 保存设备标识到本地
- 支持设备解绑（登出）
- 处理设备数量超限情况

### 4. 安全要求

- 本地加密存储用户信息
- 定期验证token有效性
- 处理token过期情况
- 防止本地时间篡改

### 5. 离线使用

- 支持长期离线使用（180天）
- 临近过期时提醒用户
- 网络异常时使用本地缓存
- 缓存过期后要求联网验证

### 6. 用户界面

- 登录/注册入口
- 显示当前登录状态
- 显示会员类型
- 显示设备数量
- 显示过期时间
- 登出功能

### 7. 异常处理

- 网络错误处理
- 账号权限变更处理
- 设备数量超限处理
- Token过期处理
- 登录失败处理

## 三、技术实现要点

### 1. 数据存储

- 用户认证信息
- 设备标识信息
- 权限缓存信息
- 本地加密方案

### 2. 网络请求

- 登录接口
- 刷新Token接口
- 登出接口
- 权限验证接口

### 3. 状态管理

- 用户登录状态
- 权限状态
- 网络状态
- 缓存状态

### 4. 兼容处理

- 保留原有激活码功能
- 新旧系统共存方案
- 数据迁移方案

## 四、开发顺序建议

1. 基础类型定义
2. 认证服务实现
3. IPC通信实现
4. 本地存储实现
5. 状态管理实现
6. UI组件开发
7. 异常处理完善
8. 测试和优化

## 五、注意事项

1. 保持与现有功能的兼容性
2. 确保离线使用体验
3. 注意数据安全性
4. 做好异常处理
5. 优化网络请求
6. 注意用户体验
