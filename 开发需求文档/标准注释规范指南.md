# TypeScript/JavaScript 标准注释规范指南

## 一、文件顶部注释规范

### 1. 基本结构

```typescript
/**
 * @file 文件名
 * @description 文件描述
 *
 * 详细说明（可选）
 *
 * @author 麦先生
 * @created 创建时间
 * @modified 最后修改时间（可选）
 * @version 版本号（可选）
 */
```

### 2. 功能列表格式

```typescript
/**
 * 主要功能：
 * 1. 功能1
 *    - 子功能1
 *    - 子功能2
 * 2. 功能2
 *    - 详细说明
 */
```

## 二、函数注释规范

### 1. 基本格式

```typescript
/**
 * 函数说明
 * @param {参数类型} 参数名 参数说明
 * @returns {返回类型} 返回值说明
 * @throws {错误类型} 可能抛出的错误（可选）
 * @example 使用示例（可选）
 */
```

### 2. 异步函数格式

```typescript
/**
 * 异步函数说明
 * @async
 * @param {参数类型} 参数名 参数说明
 * @returns {Promise<返回类型>} Promise返回值说明
 */
```

## 三、类注释规范

### 1. 基本格式

```typescript
/**
 * 类说明
 * @class
 * @classdesc 类的详细描述
 * @implements {接口名} 实现的接口（可选）
 * @extends {父类名} 继承的父类（可选）
 */
```

## 四、接口/类型注释规范

### 1. 基本格式

```typescript
/**
 * 接口说明
 * @interface
 * @property {类型} 属性名 属性说明
 */
```

## 五、变量注释规范

### 1. 基本格式

```typescript
/** 变量说明 */
const variable = value

// 或者多行格式
/**
 * 变量详细说明
 * @type {类型}
 * @constant
 */
const CONSTANT = value
```

## 六、注释书写要求

1. **完整性**

   - 必须包含必要的基本信息
   - 参数和返回值必须注明类型和说明

2. **准确性**

   - 描述必须准确反映代码功能
   - 参数说明要与实际参数一致

3. **简洁性**

   - 使用简洁清晰的语言
   - 避免冗余信息

4. **一致性**

   - 项目内保持统一的注释风格
   - 使用统一的标签顺序

5. **实时性**
   - 代码更新时同步更新注释
   - 记录重要的修改信息

## 七、常用注释标签

- `@file` - 文件说明
- `@description` - 详细描述
- `@author` - 作者信息
- `@created` - 创建时间
- `@modified` - 修改时间
- `@version` - 版本信息
- `@param` - 参数说明
- `@returns` - 返回值说明
- `@throws` - 异常说明
- `@example` - 使用示例
- `@deprecated` - 废弃说明
- `@todo` - 待办事项
- `@see` - 参考信息
- `@since` - 起始版本

## 八、最佳实践

1. **关键代码必须注释**

   - 复杂算法
   - 业务逻辑
   - 特殊处理

2. **避免无意义注释**

   - 不要注释显而易见的代码
   - 不要重复代码本身在做的事

3. **保持注释的及时更新**

   - 代码变更时同步更新注释
   - 定期检查注释的准确性

4. **使用正确的语言**
   - 使用专业准确的术语
   - 保持语言的一致性
